# OANDA OCO M1 replay protocol

**Status:** protocol and engine prepared; no OANDA data or API token is currently available, so no OANDA backtest result exists.

## Input and coverage

Input is the normalized OANDA M1/M5 parquet generated by `prepare_candles.py`. M1 midpoint OHLC plus OANDA candle `volume` feed the profile. M1 bid/ask OHLC drive entry, stop, target, and session-close execution. Session time windows come from `../rolling_6h_m5/session_coverage.csv` so the OANDA replay can be compared over the same historical windows as the FBS study; the 90% session coverage rule is evaluated using OANDA M5 bars against the median expected count from included FBS reference sessions. The FBS file supplies time-window boundaries only; the 70/30 split uses OANDA-covered sessions. The chronological 70/30 split and three development folds are then based only on OANDA-covered sessions.

## Profile

At each M5 bar open, construct the prior six-hour profile from completed OANDA M1 candles. Distribute each M1 candle's tick volume over its midpoint OHLC-intersected $0.10 rows in proportion to overlap. Use the contiguous 70% value area and POC row. Require at least 48 complete M5 bars total and 24 in each three-hour half, with at least 50% overlap of the two half-window value areas.

## Fixed variants

1. `base_oco`: first qualifying profile per session; buy limit at frozen VAL and sell limit at frozen VAH.
2. `stable_poc_050`: activate only when prior M5 close is inside current VA, directional efficiency <=0.25 computed from completed M5 closes inside the rolling six-hour time window, and older/recent-half POCs differ by <=$0.50; while active, maintain the same filters and require prior close inside frozen VA.
3. `stable_poc_100`: same as above, with POC difference <=$1.00.

Each variant freezes levels at activation, allows one cluster and one fill per session, expires after 72 M5 bars or two consecutive M5 closes outside frozen VA, targets frozen POC, and places the stop beyond the edge by 2 x six-hour median spread + $0.10.

## Execution model

A buy limit is eligible when M1 ask low <= VAL; a sell limit is eligible when M1 bid high >= VAH. If both OCO sides are touched in the same M1 candle, skip the ambiguous entry. Fill at the limit, with no price improvement. For an open trade, use bid OHLC for longs and ask OHLC for shorts. If both stop and target are reachable within one M1 candle, score the stop first. Stop gaps fill at the worse of the stop price and M1 open; target gaps may fill at a better M1 open. At session end, exit at the last executable quote close. R is measured from planned limit price to stop. This is conservative about event ordering, but assumes a passive limit fill on touch and does not model queue priority.

## Candidate gate

Require at least 20 development trades, positive net R in at least two of three chronological development folds, and positive net R in the chronological validation block. Include commissions and additional slippage in any final claim. OANDA M1 candles do not provide tick chronology, so any positive result still requires a fresh forward quote replay before strategy adoption.
